# ADR-010 — Single-Use Links to Activate an Account or Reset Its Password

## Identification

| Field | Value |
|---|---|
| Id | ADR-010 |
| Date | 2026-11-09 |
| Status | Accepted |
| Authors | Tech lead and team |
| Supersedes | none |

## Context

Accounts are now created by an administrator, who must never know their passwords,
and a forgotten password needs a way back. The application has no mail server.

| Constraint | Source |
|---|---|
| The administrator changes access without knowing the password | Requirements of the 2026-11-09 review |
| A new user sets their own first password | Requirements of the 2026-11-09 review |
| A password is stored only as a salted hash | `NFR-06` |
| No new infrastructure before the delivery of 2026-11-14 | Course calendar |

## Decision

**We decided:** an administrator generates a single-use link, shown once, and hands
it to the person, who chooses the password on it; one table,
`identity.account_tokens`, holds both purposes.

The tiebreaker was the absence of mail: the link needs nothing new to run, and the
administrator still never handles a password.

## Alternatives evaluated

| Alternative | Pros | Cons | Verdict |
|---|---|---|---|
| Link generated by the administrator | No mail server; the administrator never knows a password | The administrator must deliver it | Chosen |
| Temporary password | Simple | The administrator knows it, however briefly | Rejected by the requirement |
| Link sent by email | Self-service from sign-in | A mail server, and a service more in every environment | Too large for the deadline |

## Rules

| Rule | Value |
|---|---|
| Token | 256 random bits, Base64URL; only its SHA-256 is stored |
| Lifetime | Activation 72 hours; password reset 30 minutes |
| Use | Once. A new link for an account cancels the earlier ones |
| Invalid token | One and the same `400`, whatever the reason |
| In the portal | After `#` in the link, so it never reaches a server log |

## Consequences

| Kind | Consequence |
|---|---|
| Positive | No password ever passes through an administrator |
| Cost | `password_hash` becomes optional until activation |
| Risk | An administrator could use a link they generated; the row records who generated it |
| Risk | A bearer token already issued stays valid until it expires, at most `AUTH_JWT_EXPIRY_SECONDS` |
| Risk | If the only administrator forgets the password, nobody can generate a link; the manual describes the recovery by console |
